# グラフィックの追加手順

ここに決められた名前で PNG を置くと、コードで手続き的に描いている仮の絵を
自動的に上書きする。**コードの変更は不要。**

ファイルが無いものはこれまで通り仮の絵のまま描かれるので、
1 枚ずつ置き換えていける。

## 手順

1. 下の一覧から描きたいものを選ぶ
2. **64 × 40 ピクセルの透過 PNG** を作る
3. 一覧のパスと同じ場所・同じ名前で保存する
4. ブラウザをリロードする

以上。ビルドもコード変更も要らない。

## 画像の仕様

- **128 × 72 ピクセルの透過 PNG**
- 全レイヤーが同じ 128×72 の枠。**この枠の中で位置合わせを済ませる**（アンカー指定は不要）
- サメ本体は枠の中の **x:16〜111 / y:14〜57**（96×44）。体の中心線は **y:36**
- サメは**右を向いている**（頭が右、尾が左）
- 拡大縮小は描画側で行うので、等倍のドット絵をそのまま置けばよい

```
      0          16                                111        128
    0 ┌──────────────────────────────────────────────────────┐
      │                                                      │
   14 │          ┌────────────── 96 ──────────────┐          │
      │          │                                │          │
   36 │ - - - - -│- - - - - 体の中心線 - - - - - -│- - - - - │  ← 尾が左 / 頭が右
      │          │              44                │          │
   57 │          └────────────────────────────────┘          │
      │                                                      │
   72 └──────────────────────────────────────────────────────┘
```

枠が本体より広いのは、装飾（棘・砲塔・オーラ・火の粉など）がはみ出せるようにするため。

### base.png だけは 96×44

`base.png` はサメ本体そのものなので、枠ではなく **96 × 44** で作る。
描画側が枠の中の正しい位置（x:16 / y:14）に配置する。

### 原本は art-src/ に置く

編集ソフトからの書き出しは `art-src/` に置き、次のコマンドで変換する。

```bash
node tools/rebuild-base.ts
```

背景の切り抜きなどで色が散ったり、非整数倍のリサンプルで
ドット格子が崩れていても、パレットに量子化し直して 96×44 に戻す。
どんなサイズ・どんな汚れ方の書き出しでも同じ処理で通る。

## 装飾は絵の輪郭に自動で追従する

棘・砲塔・キノコ・装甲板などの位置は、**`base.png` の α を列ごとに走査して求めている**。
式で決め打ちしていないので、**base.png を描き替えると装飾の位置も勝手に付いてくる**。

双頭化と三頭化に至っては、**`base.png` の頭の部分を切り出して貼っている**。
頭を別途描く必要はなく、絵柄も構造的に一致する。

## 画像が要らない変異（12 種）

大きさ・色・数・透明度を変えるだけで、絵そのものを持たない。

```
高速遊泳    少し細く + 淡い青に寄せる
白化        白に寄せる
猛毒        紫緑に寄せる + 泡
灼熱        赤橙に寄せる
高圧適応    1.12 倍 + 青灰に寄せる
飛行        傾ける + 淡く寄せる
巨大化      1.5 倍に拡大
ダブル      同じ絵を 2 匹に複製
トリプル    同じ絵を 3 匹に複製
幽体化      半透明にする
双頭化      base.png の頭を切り出して上にずらす
三頭化      base.png の頭を切り出して上下にずらす
```

これらの数値（どの色に何 % 寄せるか、何倍にするか）は
`src/render/sharkSprite.ts` の `VISUALS` に書いてある。
**そこだけは絵ではなく数字なので、変えたいときはコードを触る**（1 行）。

## 描くときに知っておくと良いこと

### 重ねる順番

```
1. 尾           part/tail/*
2. 本体         base
3. 胴の置換     part/body/*
4. 頭の置換     part/head/*
5. 追加部位     attach/*        （複数ある場合は変異の定義順）
6. 色の塗り分け                  （画像ではなく数値で処理）
7. エフェクト   overlay/*       （複数ある場合は変異の定義順）
8. 変形                          （拡大・複製・傾き・透明度）
```

`attach` は色の塗り分けより**前**なので、色を変える変異と一緒に付くと色が乗る。
`overlay` は塗り分けの**後**なので、色に影響されず元の色のまま出る。

### 色の塗り分けは体を等分する

色を変える変異を複数持つと、体が長さ方向に等分され、区画ごとに別の色になる。
2 つなら半分ずつ、3 つなら 3 等分。
そのため **base は色を寄せられる前提の、中間的な明度で描く**とよい。

### ファイル名は変異の内部 ID

表示名を変えてもファイル名は変わらない。
たとえば `attach/ancient.png` は「超古代」、`attach/autonomous.png` は「機械兵装」。

## 確認のしかた

開発サーバを起動して、画面右下の `DEV` → **スプライト合成を確認** を開くと、
全 32 種の単体と、組み合わせの例が一覧で並ぶ。置いた画像がどう合成されるか確認できる。

## うまく反映されないとき

- ファイル名とパスが一覧と一致しているか
- 透過 PNG になっているか（背景が塗り潰されていないか）
- ブラウザのキャッシュ（スーパーリロード）

ファイルが無い間はコンソールに 404 が出るが、これは想定どおりで動作に影響しない。
