# 手触り（Game Feel / Juice）

「触っていて気持ちいい」を分解する。実装コストの割に効果が最も大きい領域。

## 1. 語彙の出どころ

この分野の名前を作ったのは **Steve Swink『Game Feel: A Game Designer's Guide to
Virtual Sensation』（2008）**。

その後、実践側で決定的だったのが 2 本の講演。

- **「Juice it or Lose It」**（Martin Jonasson / Petri Purho, Nordic Game Jam 2012）
  動くだけのプロトタイプに演出を足していくと、ゲームがどう生き返るかを実演した
- **「The Art of Screenshake」**（Jan Willem Nijman / Vlambeer, 2013）
  Nuclear Throne を暴力的で即物的に感じさせている**約 30 個の小技**を高速で列挙する。
  マズルフラッシュ、ヒットストップ、カメラキックなど

この 3 つが現在の共通語彙になっている。

## 2. Game Feel の三層構造

Swink の分解。**順番に依存関係がある**のが重要。

| 層 | 内容 | 壊れ方 |
|---|---|---|
| 1. **リアルタイム制御** | 操作が意図に即座に反応する | 入力遅延、取りこぼし |
| 2. **模擬空間** | 物理が予測可能に振る舞う。重さと衝突がある | ふわふわする、すり抜ける |
| 3. **磨き（Juice）** | フィードバックと誇張 | 無音、視覚的に死んでいる |

**Juice は既に機能しているものを増幅するだけで、遅い入力を救えない。**
ここを取り違えると、演出を足しても手応えが出ない。

> 「Juice とは、行為を単に正しいだけでなく満足のいくものにする、
> フィードバックと誇張の層である」

## 3. 具体的な数値レシピ

調べた中で数値が明示されていたもの。

### 入力の寛容さ

| 技法 | 内容 | 目安 |
|---|---|---|
| コヨーテタイム | 足場を離れた後も数フレームはジャンプを受け付ける | **150ms 未満**に収める |
| 入力バッファ | 押されたボタンを数フレーム覚えておき、有効になった瞬間に発火 | 同上 |

### 即時フィードバック

| 技法 | 内容 | 目安 |
|---|---|---|
| **ヒットストップ** | 着弾時に画面を止めて重さを出す | **40〜80ms** |
| **画面揺れ** | カメラを数ピクセル蹴る | **威力に比例させる**（拳銃とロケットで同じにしない） |
| **スカッシュ&ストレッチ** | 着地で潰し、跳躍で伸ばす | — |
| **パーティクル / フラッシュ** | 接触した瞬間に弾けさせる | — |
| **ノックバック** | 攻撃側と被弾側を引き離す。カメラや武器も反動 | — |

### 動きの質

- **線形補間をやめる。** イージング曲線（速い→遅い、またはその逆）に置き換える
- UI・カメラ・アニメーションの全部に適用する

### 音

音はアニメーションと**同等の重み**を持つ。無音は衝撃を殺す。

## 4. よくある失敗

出典で名指しされていたもの。

- **磨く前の入力遅延を放置する**（何を足しても無駄になる）
- 線形の動き
- **見境のない画面揺れとフラッシュ**
- 無音の行為
- モーション過敏への配慮を怠る（`prefers-reduced-motion`）
- **手触りの反復を開発後期に回す**

そして「手触りは観察ではなく**プレイして**確かめる」こと。
グレーボックスのプロトタイプを先に作る。

## この企画への当てはめ

### 三層構造で自己診断

| 層 | 現状 |
|---|---|
| リアルタイム制御 | クリックは即座に反映される。**問題なし** |
| 模擬空間 | 突撃ビュワーの物理（跳ね返り・重力・回転）はある。**及第点** |
| 磨き | クリックの脈動と飛ぶ数値、深度突破の一閃、ドラフトの時間差表示。**着手済みだが薄い** |

**1 層目と 2 層目が先に立っているので、3 層目に投資する価値がある状態**にはなっている。

### まだ入れていないもの（効きそうな順）

1. **ヒットストップ**。建物を破壊した瞬間に 40〜80ms 止める。
   いま破壊は HP バーが減るだけで、瞬間の重さがない。
   突撃ビュワーは自前の rAF ループなので、`dt` を数フレーム 0 にすれば実装できる
2. **画面揺れを威力に比例させる**。通常建築物とボスで揺れ幅を変える。
   いまは建物が光るだけ
3. **音**。完全に無音。出典が「音はアニメーションと同等の重み」と言っている以上、
   ここが最大の欠落。Web Audio API で短い矩形波を鳴らすだけでも変わる
4. **スカッシュ&ストレッチ**。サメが建物に当たる瞬間に潰れる。
   ドット絵なので縦横比を 1 フレームだけ変えるだけで出せる
5. **イージング**。HP バーが `transition: width 80ms linear` になっている。
   減る方向は速く始めて遅く終わる曲線にすると、削れている感じが出る

### 入力の寛容さについて

コヨーテタイムやバッファは**このゲームには該当しない**（アクション操作がないため）。
ただし読み替えると、

- **連打時のクリック取りこぼし**が起きていないかは確認する価値がある
- ドラフトのカードを押した瞬間に次のドラフトが出る場合、
  **誤爆を防ぐ短い無効時間**（150ms 未満）を入れると事故が減る。
  実際、デバッグ中に連続ドラフトを一気に消化してしまう挙動を観測している

### 見境のない演出への警戒

出典が明示的に戒めている点。本作は「全部乗せ」の思想なので、
**変異の演出は盛ってよいが、UI の演出は抑制する**という線引きを持っておく。
いま `prefers-reduced-motion` は全演出に入れてあるので、そこは守れている。
