# インクリメンタルゲームの解剖

## 1. なぜ数字が増えると面白いのか

調べた範囲で、繰り返し挙げられていた要因は 4 つ。

### 発見（Discovery）

Envato Tuts+ の分析では、面白さの多くは**発見**にあるとされている。
極めて単純な初期状態から始まり、進むほど複雑さが渦を巻いて増えていく。
新しい機能や隠れた仕組みが明らかになること自体が報酬になる。

設計上の含意として、コンテンツは**既知の未知**（あることは分かるが中身は知らない）か
**未知の未知**（あることすら知らない）として置くべきで、
最初から全部見せてはいけない、と述べられている。

### 恣意的なシステムを最適化する快感

「人間は恣意的なシステムを最適化することを楽しむ」という指摘が複数のソースで出てくる。
何を買うか、どの順で買うかという最適化問題が、それ自体で駆動力になる。

### 途切れない達成感

Bugnet の記事では、最も基本的なレベルで
「アイドルゲームは継続的な達成感を提供する」と要約されている。
プレイヤーが操作しなくても進行するため、達成が途切れない。

### 常に手の届く次の目標

満足のいく成長ループとは、蓄積した資源を「蓄積速度を上げるもの」に使うループであり、
**次の目標が常に、届きそうな距離にあって、かつ到達する価値がある**状態を保つこと、
と説明されている。

## 2. コストと生産の数学

ここが最も具体的で、そのまま使える部分。

### コスト式

```
cost_next = cost_base × growth ^ owned
```

実在タイトルの growth 値:

| タイトル                            | growth       |
| ----------------------------------- | ------------ |
| Cookie Clicker（全建物共通）        | 1.15         |
| AdVenture Capitalist（10 種で個別） | 1.07 〜 1.15 |

**1.07 〜 1.15 の範囲が「バランスが取れて満足度が高い」**とされている。

### 生産式

```
production_total = (production_base × owned) × multipliers
```

生産は**線形または多項式**で伸びる。コストが指数、生産が線形。この差が全てを作る。

Clicker Heroes の Treebeard は 1 段階ごとに +5 の固定加算で、`y = 5x` という単純な直線。

### なぜこの組み合わせが機能するのか

Tuts+ の説明では、2 本の線の**開いていく差**が、
常に変動するコスト対効果比を生む。結果として:

- **収穫逓減** — 単一の強化を無限に伸ばせない
- **最適解が動き続ける** — 相対的な価値が絶えず入れ替わり、再評価を強いる
- **ペースの変化** — 序盤は速く、コストが指数で伸びるにつれ劇的に減速する

数学的な必然として、
**指数成長は係数に関係なくいずれ多項式成長を追い越す**。
これがリセット（プレステージ）を不可避にする。

### まとめ買いの式

反復せずに計算できる形が導かれている。

```
n 個買う総額     cost = b × r^k × (r^n − 1) / (r − 1)
買える最大個数   max  = floor( log_r( c(r−1) / (b × r^k) + 1 ) )

b = 基礎価格 / r = 伸び率 / k = 現在の所持数 / c = 所持通貨
```

### 買う順の比較式

どの強化を先に買うべきかを比較する式:

```
cost_a / nps + cost_a / (nps + rate_a)

nps = numbers per second（現在の毎秒生産量）
```

これで**意図しない時間の壁**を検出でき、
最適プレイが設計者の意図した速度で進むことを保証できる、とされている。

### 知覚の話

Eric Guan は心理物理学を引いて、人間は変化を**対数的に**知覚すると述べている。
豆が 5 個から 6 個に増えたのは分かるが、100 個から 101 個は分からない。

彼の解法は二重の指数スケーリングで、
**生産は 1 段階ごとに ×1.1、コストは ×1.15**。
気づける進歩を保ちながら、自然に減速させる。

## 3. プレステージ（リセット）の数学

リセットの目的は 2 つあると整理されている。
**梯子を登り直す感覚**を作ること、そして**数字を管理可能な範囲に押し戻す**こと。

獲得するプレステージ通貨の計算方式で、プレイヤーの行動が根本的に変わる。

| タイトル             | 計算元           | 式                       | 通貨を 2 倍にするのに必要な倍率 |
| -------------------- | ---------------- | ------------------------ | ------------------------------- |
| Realm Grinder        | 最大獲得額       | 平方根                   | 約 **4 倍**                     |
| AdVenture Capitalist | 生涯獲得額       | `150·√(c_L / 10^15)`     | 約 **4 倍**                     |
| Cookie Clicker       | 生涯獲得額       | `∛(c_L / 10^12)`         | 約 **8 倍**                     |
| Egg, Inc.            | **そのランのみ** | `Δp = (c_R / 10^6)^0.14` | 約 **128 倍**（2^7）            |
| Clicker Heroes       | 購入した強化の数 | 対数的                   | —                               |

**生涯累計型**は同じ地点で何度リセットしても通貨が増えるため、常に前進する動機になる。
**ラン単独型**（Egg, Inc.）は曲線を平坦にし、
最適な地点で繰り返し稼ぐ形になる。オフライン進行に上限があるゲームで有用。

---

## 4. ペーシングと運用

- Cookie Clicker と AdVenture Capitalist はどちらも、
  **最初の 8〜10 時間**で急速に進み、その後は伸びが緩やかになる曲線を描く
- 古い生成器を死なせないため、
  **所持数 25 / 50 / 100 個などの節目で倍率を与える**手法が使われる。
  これがないと新しい生成器が常に最適解になり、購入判断が消える
- 再訪問の頻度を複数の時間軸で設計する例（Eric Guan）:
  20 分で満タンになる生産、5 時間で満タン、2 日で満タン、を並走させる。
  頻繁に開く人と 1 日 1 回の人が、それぞれ別の対象を最適化できる

## 5. 先人の失敗から

Game Developer に載っていた個人開発者の反省が、そのまま参考になる。

- **締切を切らなかったこと**が最大の失敗。1 ヶ月の締切があればスコープが膨れなかった
- **バランス調整の自動化を最初からやるべきだった。**
  「インクリメンタルのバランス調整は難しい。最初から自動化することが重要」と明言されている。
  コンテンツを足すたびに手で値をいじるのは持続しない
- 描画とゲームロジックを早い段階で分離したことは正解だった
- 設計が「長いプレイ時間 / 十分なコンテンツ量 / 面白さ」のうち**同時に 2 つまで**しか満たせなかった

## この企画への当てはめ

### すでに合っているもの

- **コスト伸び率 1.13 〜 1.20** は実在タイトルの 1.07〜1.15 とほぼ同じ帯にある
- **バランス調整の自動化**は最初からやっている（`src/sim/`）。
  先人が「最大の後悔」として挙げた点を回避できている
- **描画とロジックの分離**（`src/game/` が React に依存しない）も同じく
- **発見の設計**として、変異のレアリティが累計生産数に連動する仕組みは
  「既知の未知」を作れている

### 検討に値するもの

- **買う順の比較式**（`cost/nps + cost/(nps+rate)`）をシミュレータに入れると、
  「施設の差別化が弱い」という既知の問題を数値で診断できる。
  いま購入比率を変えても到達深度がほぼ変わらないのは、
  どの施設も同じ比率になっている可能性がある
- **所持数の節目で倍率**という手法は未導入。
  設備連動（温度管理・給餌連動など）が近いが、あれは恒久強化側にある。
  ラン内で「培養槽 25 個目で全体 ×2」のような節目を置くと、
  購入判断に山ができる
- **プレステージ通貨の式**は現在 `√総戦果 × 0.3 × (1 + 0.5 × 突破深度)`。
  分類上は AdVenture Capitalist 型（生涯ではなくラン単位の平方根）。
  Egg, Inc. 型（指数 0.14 のような強い圧縮）に寄せると、
  1 ラン内で稼ぎ切る設計になり、周回の粒度が変わる
- **再訪問の複数時間軸**は、オフライン進行を持たない本作には直接適用できない。
  ただし「ラン内で 20 秒 / 60 秒 / 3 分の 3 つのリズムを並走させる」と読み替えると使える

### 意図的に外しているもの

- **オフライン進行**。アイドルゲームの定番だが、本作は
  「ランは必ず終わる」設計なので入れない
- **8〜10 時間の進行曲線**。本作は 1 ラン 3〜8 分の周回型なので、
  同じ曲線を目指す必要はない

## 余談・細部

要約に載せるほどではないが、後から効いてくる周辺の話。

### growth 値は「何個ごとに価格が倍になるか」で読む

`ln 2 / ln(growth)` を計算すると、数字の意味が体感に変わる。

| growth | 価格が倍になる所持数 |
| ------ | -------------------- |
| 1.07   | 10.2 個              |
| 1.13   | 5.7 個               |
| 1.14   | 5.3 個               |
| 1.15   | 5.0 個               |
| 1.18   | 4.2 個               |
| 1.20   | 3.8 個               |

1.07 と 1.15 は見た目の差が小さいが、**同じ通貨で買える個数が倍違う**。
「1.07〜1.15 が良い」と言われている帯は、実際にはかなり広い。

本作の施設 5 種は 5.7〜3.8 個の帯に収まっている。
つまりどれも「5 個買うごとに倍」に近い形をしている。

### 買う順の比較式は、収入が育つと縮退する

```
cost / nps + cost / (nps + rate)
```

`rate` が `nps` に対して小さくなると、この式は `2 × cost / nps` に潰れる。
**順位が価格だけで決まるようになり、施設ごとの `rate` が効かなくなる。**

実測で「購入比率を変えても到達深度がほとんど変わらない」となっているのは、
これで説明がつく。逃がすなら価格ではなく**効果の形**を変える必要がある
（乗算にする、条件付きにする、上限を設ける、他の施設の所持数に依存させる）。

### まとめ買いの式の落とし穴

- **`r = 1` で 0 除算。** 等比の総和の式なので、線形コストの施設を混ぜると壊れる
- **最大個数の式は負を返しうる。** `log` の中身が 1 未満になると負になるため、
  `floor` の前に `max(0, …)` が要る
- **浮動小数の限界。** growth 1.15 なら 5,078 個目で `Infinity` になる
  （1.13 で 5,807 個、1.20 で 3,893 個）。
  通常は届かないが、本作は上限のない強化を入れたので頭の隅に置いておく

### プレステージ指数の一般則

通貨を 2 倍にするのに必要な元手の倍率は `2^(1/p)` で決まる。

| 圧縮    | p     | 必要な倍率 |
| ------- | ----- | ---------- |
| 平方根  | 1/2   | 4 倍       |
| 立方根  | 1/3   | 8 倍       |
| 0.14 乗 | 0.14  | 141 倍     |
| 1/7 乗  | 0.143 | 128 倍     |

表にある Egg, Inc. の「0.14 で 128 倍」は `1/7 = 0.1428…` を丸めた言い方。
0.14 ちょうどなら 141 倍になる。**丸めの向きで 1 割ずれる**ので、
実装するときは指数をどちらで持つか決めておくこと。

本作は `p = 1/2`、つまり AdVenture Capitalist 型。

### 二重指数の実効値

「生産 ×1.1 / コスト ×1.15」は、言い換えると
**単価が 1 段階あたり 1.0455 倍**（= 1.15 / 1.1）になるということ。
単価が倍になるまで 15.6 段階かかる。

「気づける進歩」と「自然な減速」の両立は、
この **1.0455 という非常に緩い数字**の上に成立している。
0.15 と 0.10 の差ではなく、その比を見ないと設計意図が読めない。

### 「対数的に知覚する」の正式名称

**Weber–Fechner の法則。** 刺激の弁別閾は刺激の強度に比例する
（100 個に対する 1 個は、5 個に対する 1 個より気づきにくい）。

1 段階 ×1.1、つまり +10% という刻みは、
多くの感覚での弁別閾（数 % 〜 10% 前後）と同じオーダーにある。
Eric Guan の 1.1 は経験則に見えて、実は知覚の閾値ぎりぎりを狙った値。

### 節目ボーナスの間隔は、等差に見えて等比

25 / 50 / 100 という並びは等間隔に見えるが、growth 1.15 で価格に直すと
1 個目に対して **25 個目が 33 倍、50 個目が 1,084 倍、100 個目が 117 万倍**。

**後ろの節目ほど遠い。** 到達間隔を体感で揃えたいなら、
節目そのものを等比ではなく、もっと詰めた並びに置く必要がある。
